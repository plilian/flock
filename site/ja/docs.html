FLOCK / ドキュメント

Flockを、選んだ
ワークスペースで。

AIホスト用のネイティブパッケージを導入し、自分の資料やシナリオを使ってください。Flockはローカルで動くワークフローであり、ホスト型シミュレーションサービスではありません。

このページの内容 インストール 最初のプロジェクト ワークフロー Evidence Audit Scenario Lab シミュレーションの仕組み よくある質問 プライバシーとデータ トラブルシューティング ライセンス

01 / インストール

ホストに合わせて導入

Flockは対応するAIエージェントホストごとに、ネイティブプラグインまたは拡張機能として配布されています。各パッケージには共通のワークフロースキルと、モデルを呼び出さないPythonヘルパーが含まれます。推論はホストのセッションが行い、ヘルパーはグラフとシミュレーションデータを検証・保存します。

すべてのパッケージは公開GitHubリポジトリから直接インストールできます。Flockはホスト型モデルを提供せず、Flock専用APIキーも必要ありません。利用する製品の手順に従ってホストにログインまたは設定してください。プロバイダーの選択肢や利用上限はホストごとに異なります。

共通要件

  • Python 3.11以降、およびホスト環境でのワークスペース／ターミナル利用。
  • 公開リポジトリからパッケージを導入するためのGit。
  • Flockのデータフォルダー： .flock/
  • 対応ホストとモデルへのアクセスは各自で用意してください。Flockが開発者のアカウントを共有することはありません。

01 / CODEX · ネイティブプラグイン

Codex

Flockマーケットプレイスを追加し、プラグインをインストールします：

codex plugin marketplace add plilian/flock
codex plugin add flock@flock

Codexを開くか再起動し、Flockを使うよう依頼するか、次のスキルを呼び出します： $flock スキル。

02 / CLAUDE CODE · ネイティブプラグイン

Claude Code

Claude CodeのターミナルでFlockマーケットプレイスを追加してインストールします：

claude plugin marketplace add plilian/flock
claude plugin install flock@flock

必要に応じてClaude Codeを再起動または再読み込みし、ワークスペースを開いてClaudeに次のスキルを使うよう依頼します： flock スキル。

03 / GEMINI CLI · ネイティブ拡張

Gemini CLI

リポジトリURLからFlockをインストールします：

gemini extensions install https://github.com/plilian/flock

指示があればCLIを再起動し、Gemini CLIにFlockスキルを使うよう依頼します。Gemini CLIの認証とモデル利用はGoogle／Geminiの設定に従います。

04 / QWEN CODE · ネイティブ拡張

Qwen Code

リポジトリURLからFlockをインストールします：

qwen extensions install https://github.com/plilian/flock

指示があればCLIを再起動し、次を呼び出します： /flock:flock またはQwen Codeにそのスキルを使うよう依頼します。Qwenのログイン、プロバイダー設定、利用上限はQwen Code側で管理されます。

05 / DEEPSEEK HARNESS · 開発者向けプレビュー

DeepSeek Harness

Harnessは独立した開発者向けプレビューのプラグインホストです。リポジトリをクローンし、HarnessプロファイルにFlockをインストールします：

git clone https://github.com/plilian/flock.git
cd flock
dsh plugin --profile web add ./plugins/deepseek-harness

このパッケージはDeepSeek Harness専用です。DeepSeekのチャットサイト向けプラグインではなく、DeepSeek APIも呼び出しません。Harnessで利用できるモデルは、対応するプロバイダー設定に依存し、別途設定が必要な場合があります。

これらのパッケージはGitHubからインストールできますが、各社が管理するプラグインディレクトリへの掲載ではありません。「Flock APIキー不要」とは、Flock独自の認証情報やモデルサービスが不要という意味です。各ホストが求める認証やプロバイダー設定は別途必要です。

02 / 最初のプロジェクト

ワークスペースを初期化

Flockのデータを保存するワークスペースでホストを開きます。資料を配置または添付し、エージェントに次のように依頼します：

Flockで「交通調査」というプロジェクトを初期化してください。

FlockはSQLiteグラフデータベースと実行記録を .flock/ フォルダーに保存します。プロジェクトごとに別のワークスペースフォルダーを使ってください。ヘルパーはグラフや実行データを誤ってGitにコミットしないようignoreルールを追加します。資料は元の場所に残り、Flockは資料名と引用情報だけを保存します。全文のコピーは保存しません。

03 / ワークフロー

根拠からシミュレーションへ

グラフを構築

選択した資料からグラフを抽出するよう、ホストのエージェントに依頼します。現在のモデルがオントロジー、エンティティ、関係を特定し、Flockが出典情報を検証してSQLiteグラフに保存します。Mermaid図、検索、グラフ統計で確認できます。

Flockで./sourcesから知識グラフを作り、主要な関係を表示してください。

合成コミュニティを作成

探索する集団と問いを説明します。ホストのモデルはグラフ内のエンティティをもとにプロフィールを作成し、資料に基づかない仮定を明示します。

シナリオを探索

Reddit風またはTwitter風の議論を選び、シナリオとラウンド数を決め、実行前にプロフィールの仮定を確認します。ホストのモデルが各ラウンドの行動を生成し、Flockが検証したうえで投稿、反応、エンゲージメント数を記録します。

結果を確認し、インタビュー

記録されたタイムラインを使ってレポートを作成したり、質問に答えたり、合成エージェントへのインタビューをロールプレイできます。レポートでは計算された件数と定性的な解釈を分けます。

実行結果を見る

各ラウンドの後、Flockは次の場所にあるインタラクティブなHTMLスナップショットを更新します： .flock/runs/<run_id>/visualization.html。ラウンドを移動または再生し、合成プロフィールを確認し、返信や反応をたどり、フィードを検索して実行データをダウンロードできます。ブラウザーで直接開き、外部通信は行いません。

04 / EVIDENCE AUDIT

主張を出典までたどる

グラフ内の各エンティティと関係に、次のラベルを付けます： observed, inferred、または assumption。古い記録は確認されるまで unclassified のままです。監査では出典参照の網羅性、位置情報や引用の欠落、未使用の資料、未分類のグラフ記録を確認します。

python <helper> --workspace . graph audit

ヘルパーはローカルのJSON監査データを次の場所に保存します： .flock/audits/。引用箇所を選択した資料と照合し、意見の相違や不足している視点を見つけ、監査ファイルの隣に簡潔なMarkdownレビューを書くようホストに依頼してください。引用は追跡可能性を示しますが、主張の正しさや資料の正確性を証明するものではありません。

シミュレーションでは、事実に関する投稿にグラフ参照の evidence_refsを含められます。FlockはIDを検証し、元資料名、位置情報、短い引用をイベントとともに保存するため、再生時に合成エージェントの主張の出典を確認できます。

05 / SCENARIO LAB

基準シナリオと代替案を比較

Scenario Labでは、各バリエーションと反復実行を同じ合成プロフィール、プラットフォーム、ラウンド数、空のフィードから開始します。訂正情報の提示やモデレーターの介入など、主な条件を一度に一つだけ変更します。実行履歴は分けて保管します。

次の場所に実験仕様を保存します： .flock/staging/experiment.json 。研究課題、共通エージェント一覧、2〜6個のバリエーション、1つの基準、各バリエーション1〜5回の反復を含めます。各バリエーションにはシナリオと明示的な仮定が必要です。ホストモデルの実行回数は、バリエーション数 × 反復数 × ラウンド数 × エージェント数で増えます。

python <helper> --workspace . scenario validate --spec .flock/staging/experiment.json
python <helper> --workspace . scenario create --spec .flock/staging/experiment.json
python <helper> --workspace . scenario status --id <experiment_id>
python <helper> --workspace . scenario compare --id <experiment_id>
python <helper> --workspace . scenario visualize --id <experiment_id>
python <helper> --workspace . scenario save-report --id <experiment_id> --input .flock/staging/report.md

比較結果には、計算された行動数、参加率、立場別の件数、ラウンドごとの活動、基準との差が含まれます。各指標について保存済み反復の中央値と最小／最大値を示し、次の場所にインタラクティブな比較画面を作成します： .flock/experiments/<experiment_id>/comparison.html。各実行の再生画面へのリンクも表示します。

反復の範囲は、これらの合成実行だけを要約したものです。信頼区間でも、現実世界の結果の確率でもありません。計算された件数とホストの解釈を分け、結論にはグラフの出典と実行／イベントIDを引用してください。

06 / シミュレーションの仕組み

実行の流れ

Flockではモデルの推論と永続データを分離しています。ホストで選択中のモデルが資料とプロフィールを読み、エージェントの行動を提案して文章による分析を作成します。Pythonヘルパーはグラフ記録を保存し、行動形式を検証し、ラウンドを進めて活動数を計算します。

  • Reddit風の行動： 投稿、コメント、賛成票、反対票、コミュニティへの参加。
  • Twitter風の行動： 投稿、返信、いいね、リポスト、フォロー。
  • 保存されるデータ： 証拠の状態と引用、構造監査ファイル、エージェントプロフィール、ラウンドごとのイベント、事実行動に付く検証済み出典参照、シナリオ実験、インタラクティブHTML比較、実行ごとの再生データ、Markdownレポート。

Flockのシミュレーションは、構造化された思考実験です。実在する人々の観察、世論調査、予測ではありません。結果は選択したモデル、プロンプト、資料の品質、プロフィール、設定によって変わります。

よくある質問

Flockについてよくある質問

Flockとは何ですか？

Flockは、出典に基づく知識グラフの構築、証拠の確認、合成集団の作成、ソーシャルシナリオの探索を行うオープンソースのAIエージェントプラグインです。プロジェクトのグラフとシミュレーション実行データは、ワークスペース内のSQLiteデータベースにローカル保存されます。

Flockは実在する人々の行動を予測しますか？

いいえ。Flockは合成エージェントを使った構造化思考実験を実行します。結果は世論調査、実在する人の観察、予測ではなく、反復範囲も現実の確率を表しません。

AI APIキーやZepは必要ですか？

Flock専用のAPIキー、モデルサービス、ホスト型グラフサービス、Zep依存はありません。モデルへのアクセスは選択したホストのログインとプロバイダー設定で行います。各ホストの要件、プラン、利用上限は引き続き適用されます。

Flockはどの言語に対応していますか？

Flockスキルは英語、日本語、中国語（簡体字、zh-CN）、スペイン語、ペルシャ語に対応しています。利用者が使う言語で応答し、研究課題、合成エージェントの文章、監査、レポートもその言語で作成します。コマンド、スキーマキー、ID、固定の列挙値は変更しません。

Flockを使えるAIエージェントホストは？

FlockはCodex、Claude Code、Gemini CLI、Qwen Code向けのインストール可能なパッケージを提供しています。DeepSeek Harness向けパッケージは別途開発者向けプレビューとして公開されています。DeepSeekのチャットサイトやAPIとの連携ではありません。

グラフやシミュレーションデータはどこに保存されますか？

FlockはSQLiteグラフ、証拠監査、シナリオ実験、実行履歴、可視化データを選択したワークスペース内の .flock/ フォルダーに保存します。Flockのウェブサイトにプロジェクトデータが送信されることはありません。

07 / プライバシーとデータ

あなたのワークスペース、あなたのホスト

  • 選択したホストは、利用者自身のアクティブなセッションとプロバイダー設定を通じて、資料の抜粋とプロンプトを処理します。アカウント設定、モデルポリシー、プラン、上限はそのホストに従います。
  • FlockのPythonヘルパーはネットワークやモデルを呼び出さず、ホストの認証情報も読み取りません。グラフデータ、証拠監査、シナリオ実験、可視化、レポートを選択したワークスペース内の .flock/ フォルダーに保存します。
  • Flock専用のプロバイダーAPIキー、Zepキー、Flockアカウントは不要です。ホストの構成によっては、そのホスト用のプロバイダー認証情報が必要です。
  • 公開ウェブサイトは情報とインストール手順を提供します。シミュレーションは各利用者のワークスペースで実行され、Flockのウェブサーバーに資料、グラフ、実行履歴は届きません。
  • 資料や生成したグラフを共有する前に、ワークスペースのバックアップとGit設定を確認してください。

08 / トラブルシューティング

問題が起きたとき

ホストでFlockが見つからない

パッケージが正常に導入されたことを確認し、ホストを再起動してください。Codexでは codex plugin listを確認します。Claude Codeでは /pluginを確認します。Gemini CLIとQwen Codeでは拡張機能一覧コマンドを使います。DeepSeek Harnessプラグインは開発者向けプレビューです。

Pythonがない、または古い

Python 3.11以降をインストールし、 python をホストの実行環境で利用できることを確認してください。追加のグラフ／データベースパッケージは不要です。

グラフ検証で出典が見つからないと表示される

各エンティティと関係の参照が、次の値を使い、 source_id 候補グラフの sources 配列に存在することを確認してください。インポート前にグラフを再検証します。

Flockを削除する

ホストのプラグイン／拡張機能マネージャーでFlockをアンインストールします。アンインストールしてもワークスペースデータは削除されません。次を削除するのは、バックアップ後、または不要だと確認してからにしてください： .flock/ 。
