01 / INSTALLATION

Install Flock in Codex

Flock is a Codex plugin that packages a workflow skill and a small Python helper. Model reasoning happens in the active Codex conversation through the ChatGPT account you signed into Codex with. There is no Flock login and no shared account.

Requirements

  • Codex desktop or Codex CLI with workspace and terminal access.
  • Python 3.11 or newer available to Codex. The graph helper uses only the Python standard library.
  • Your own ChatGPT sign-in to Codex. Every user signs in separately; model usage counts against that account's plan and limits.
1

Add the Flock marketplace

codex plugin marketplace add plilian/flock
2

Install the plugin

codex plugin add flock@flock
3

Open or restart Codex

Start a conversation in the workspace where you want the graph and simulation files stored. Ask Codex to use Flock or invoke the $flock skill.

No separate LLM-provider API key or Zep key is required. Installing the plugin does not run a local web server. Flock stores its own graph and run records in a .flock/ directory inside the workspace you choose.

02 / FIRST PROJECT

Initialize a workspace

Place or attach the source documents you want Codex to analyze, then say:

$flock Initialize a Flock workspace named “Transit study”.

Flock creates a SQLite graph database and run directory under .flock/. One Codex workspace holds one Flock project; use separate workspace folders for separate projects. The generated .gitignore keeps graph and run data out of normal Git commits by default. Source documents stay where you put them; Flock stores source names and citations, not full copies.

03 / WORKFLOWS

From evidence to a run

Build the graph

Ask Codex to extract a graph from selected sources. Flock asks Codex to identify an ontology, entities, and relationships, then validates and stores source references in its SQLite graph. Inspect it with a Mermaid diagram, search, or graph statistics.

$flock Build a knowledge graph from the reports in ./sources and show me its strongest relationships.

Create a synthetic population

Describe the population and question you want to explore. Codex generates profiles grounded in graph entities and marks details that are assumptions rather than source facts.

Explore a scenario

Choose a Reddit-like or Twitter-like discussion, define its scenario and round count, and review the profile assumptions before a run. Codex generates each round's actions. Flock validates actions and records the feed, reactions, and engagement counts.

Review and interview

Codex uses the recorded timeline to write a report, answer questions, or role-play an interview with a synthetic agent. Reports keep computed counts separate from qualitative interpretation.

See the run

After each round, Flock refreshes an interactive HTML snapshot in .flock/runs/<run_id>/visualization.html. Scrub or play rounds, inspect a synthetic profile, trace recorded replies and reactions, search the feed, and download the run data. The file opens directly in a browser and makes no external requests.

04 / SIMULATION ENGINE

How a run works

Flock separates model reasoning from persistent state. Codex reads the selected evidence and profiles, proposes agent actions, and writes narrative analysis. The Flock helper stores graph records, checks action formats, advances rounds, and computes activity totals.

  • Reddit-like actions: posts, comments, upvotes, downvotes, and community joins.
  • Twitter-like actions: posts, replies, likes, reposts, and follows.
  • Saved outputs: ontology, entities, relationships, agent profiles, round-by-round events, activity statistics, interactive HTML snapshots, and Markdown reports.

The simulation is an in-product, synthetic social interaction model. It is not an observation of real people, a poll, or a forecast. Results depend on the Codex model, prompts, source quality, profiles, and chosen settings.

05 / PRIVACY AND DATA

Your workspace, your account

  • Codex processes the source excerpts and prompts needed for the workflow under the individual user's signed-in ChatGPT account settings and plan limits. See OpenAI's Codex plan guide for current account and usage details.
  • The Flock helper makes no network calls and does not read Codex credentials. It stores graph and simulation data in .flock/ in the selected workspace.
  • No separate LLM-provider API key, Zep key, or Flock account is required. Users provide their own Codex sign-in; Flock does not use a shared developer account.
  • This public website only serves information and installation instructions. The simulation runs in each user's Codex workspace; the VPS does not receive project sources, graphs, or run history.
  • Flock's Git configuration ignores .flock/. In other workspaces, the helper adds a nested ignore file so private graph data is not accidentally tracked.
  • Review your workspace backup and Git settings before sharing any source material or generated graph.

06 / TROUBLESHOOTING

If something does not work

Codex cannot find Flock

Check codex plugin list. If needed, refresh the source with codex plugin marketplace upgrade flock, then install or enable the plugin from the Codex Plugins panel.

Python is missing or too old

Install Python 3.11 or newer and make sure the python command resolves in the environment Codex uses. No additional graph or database package is required.

Graph validation reports a missing source

Make sure every entity and relationship reference uses a source_id that exists in the candidate graph's sources array. Run graph validation again before importing.

Uninstall

codex plugin remove flock
codex plugin marketplace remove flock

Uninstalling the plugin does not delete workspace data. Remove .flock/ yourself only after you have backed up or no longer need those graphs and runs.
