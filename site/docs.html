01 / INSTALLATION

Install for your host

Flock ships as a native plugin or extension package for each supported agent host. Each package provides the same workflow skill and model-free Python helper. The active host session handles reasoning; the helper validates and stores graph and simulation data.

All packages install directly from the public GitHub repository. Flock does not provide a hosted model or require a Flock API key. Sign in or configure the selected host according to that product's own setup; provider options and usage limits vary by host.

Shared requirements

  • Python 3.11 or newer and workspace/terminal access in the host environment.
  • Git to install packages from this public repository.
  • A workspace where Flock can create a .flock/ folder.
  • Your own supported host installation and model access. Flock never shares the developer's account.

01 / CODEX · NATIVE PLUGIN

Codex

Add the Flock marketplace and install its plugin:

codex plugin marketplace add plilian/flock
codex plugin add flock@flock

Open or restart Codex, then ask it to use Flock or invoke the $flock skill.

02 / CLAUDE CODE · NATIVE PLUGIN

Claude Code

Add the Flock marketplace and install from a Claude Code terminal:

claude plugin marketplace add plilian/flock
claude plugin install flock@flock

Restart or reload Claude Code if needed, open your workspace, and ask Claude to use the flock skill.

03 / GEMINI CLI · NATIVE EXTENSION

Gemini CLI

Install Flock from the repository URL:

gemini extensions install https://github.com/plilian/flock

Restart the CLI if prompted, then ask Gemini CLI to use the Flock skill. Gemini CLI authentication and model access follow your Google/Gemini setup.

04 / QWEN CODE · NATIVE EXTENSION

Qwen Code

Install Flock from the repository URL:

qwen extensions install https://github.com/plilian/flock

Restart the CLI if prompted, then invoke /flock:flock or ask Qwen Code to use that skill. Qwen sign-in, provider configuration, and usage limits are managed by your Qwen Code setup.

05 / DEEPSEEK HARNESS · DEVELOPER PREVIEW

DeepSeek Harness

Harness is a separate developer-preview plugin host. Clone the repository and install Flock into a Harness profile:

git clone https://github.com/plilian/flock.git
cd flock
dsh plugin --profile web add ./plugins/deepseek-harness

This package targets DeepSeek Harness only. It is not a plugin for the DeepSeek chat website, and it does not call the DeepSeek API. Harness model access depends on the provider configuration supported by Harness and may require separate setup.

These packages are installable from GitHub. They are not listings in vendor-managed plugin directories. “No Flock API key” means Flock has no separate credential or model service; it does not remove authentication or provider configuration required by an individual host.

02 / FIRST PROJECT

Initialize a workspace

Open the host in the workspace where you want Flock data stored. Place or attach the source documents, then ask its agent:

Use Flock to initialize a project named “Transit study”.

Flock creates a SQLite graph database and run directory under .flock/. Use a separate workspace folder for each project. The helper adds an ignore rule so graph and run data are not accidentally committed to Git. Source documents stay where you put them; Flock stores source names and citations, not full copies.

03 / WORKFLOWS

From evidence to a run

Build the graph

Ask your host's agent to extract a graph from selected sources. The active model identifies an ontology, entities, and relationships; Flock validates and stores source references in its SQLite graph. Inspect it with a Mermaid diagram, search, or graph statistics.

Use Flock to build a knowledge graph from ./sources and show its strongest relationships.

Create a synthetic population

Describe the population and question you want to explore. The host model generates profiles grounded in graph entities and marks details that are assumptions rather than source facts.

Explore a scenario

Choose a Reddit-like or Twitter-like discussion, define its scenario and round count, and review the profile assumptions before a run. The host model generates each round's actions. Flock validates actions and records the feed, reactions, and engagement counts.

Review and interview

Use the recorded timeline to write a report, answer questions, or role-play an interview with a synthetic agent. Reports keep computed counts separate from qualitative interpretation.

See the run

After each round, Flock refreshes an interactive HTML snapshot in .flock/runs/<run_id>/visualization.html. Scrub or play rounds, inspect a synthetic profile, trace replies and reactions, search the feed, and download the run data. It opens directly in a browser and makes no external requests.

04 / EVIDENCE AUDIT

Trace claims to sources

Label each graph entity and relationship as observed, inferred, or assumption. Older records stay unclassified until reviewed. The audit checks source-reference coverage, missing locators or excerpts, unused sources, and unclassified graph records.

python <helper> --workspace . graph audit

The helper saves a local JSON audit under .flock/audits/. Ask the active host to check the cited excerpts against the selected source documents, identify disagreements and missing viewpoints, and write a concise Markdown review beside the audit file. A citation indicates traceability; it does not verify a claim or prove the source is accurate.

During simulations, factual posts can carry graph-backed evidence_refs. Flock validates those IDs and saves the original source name, locator, and short excerpt with the event, so a run replay can show where a synthetic agent's factual claim came from.

05 / SCENARIO LAB

Compare a baseline with alternatives

Scenario Lab starts each variant and replicate with the same synthetic profiles, platform, round count, and empty feed. Change one major condition at a time, such as whether a correction appears or a moderator intervenes. Keep run histories separate.

Save an experiment spec under .flock/staging/experiment.json with a research question, shared agent roster, 2–6 variants, one baseline, and 1–5 replicates per variant. Each variant includes its scenario and explicit assumptions. The number of host-model runs grows with variants × replicates × rounds × agents.

python <helper> --workspace . scenario validate --spec .flock/staging/experiment.json
python <helper> --workspace . scenario create --spec .flock/staging/experiment.json
python <helper> --workspace . scenario status --id <experiment_id>
python <helper> --workspace . scenario compare --id <experiment_id>
python <helper> --workspace . scenario visualize --id <experiment_id>
python <helper> --workspace . scenario save-report --id <experiment_id> --input .flock/staging/report.md

The comparison reports computed action counts, participation, stance counts, round activity, and baseline deltas. It shows each metric's median and min/max across the saved replicates and creates an interactive comparison at .flock/experiments/<experiment_id>/comparison.html, with links to each run replay.

Replicate ranges summarize only these synthetic runs. They are not confidence intervals or probabilities about real-world outcomes. Keep computed counts separate from the host's interpretation and cite graph sources and run/event IDs in any written conclusions.

06 / SIMULATION ENGINE

How a run works

Flock separates model reasoning from persistent state. Your host's active model reads selected evidence and profiles, proposes agent actions, and writes narrative analysis. The Python helper stores graph records, checks action formats, advances rounds, and computes activity totals.

  • Reddit-like actions: posts, comments, upvotes, downvotes, and community joins.
  • Twitter-like actions: posts, replies, likes, reposts, and follows.
  • Saved outputs: evidence statuses and citations, structural audit files, agent profiles, round-by-round events, validated source references on factual actions, scenario experiments, interactive HTML comparisons, per-run replays, and Markdown reports.

A Flock simulation is a structured thought experiment. It is not an observation of real people, a poll, or a forecast. Results depend on the selected model, prompts, source quality, profiles, and settings.

07 / PRIVACY AND DATA

Your workspace, your host

  • The selected host processes source excerpts and prompts through the user's own active session and provider setup. Its account settings, model policies, plan, and limits apply.
  • The Flock Python helper makes no network or model calls and does not read host credentials. It stores graph data, evidence audits, scenario experiments, visualizations, and reports in .flock/ in the selected workspace.
  • Flock requires no separate provider API key, Zep key, or Flock account. Some host configurations may require their own provider credentials.
  • The public website serves information and installation instructions. Simulations run in each user's workspace; the Flock website server does not receive project sources, graphs, or run history.
  • Review your workspace backups and Git settings before sharing source material or generated graphs.

08 / TROUBLESHOOTING

If something does not work

The host cannot find Flock

Confirm the package installed successfully and restart the host. In Codex, check codex plugin list; in Claude Code, check /plugin; in Gemini CLI and Qwen Code, check their extension list commands. DeepSeek Harness plugins are still in developer preview.

Python is missing or too old

Install Python 3.11 or newer and make sure python resolves in the host's execution environment. No additional graph or database package is required.

Graph validation reports a missing source

Make sure each entity and relationship reference uses a source_id that exists in the candidate graph's sources array. Run graph validation again before importing.

Remove Flock

Use the host's plugin or extension manager to uninstall Flock. Uninstalling does not delete workspace data. Remove .flock/ only after backing up or confirming you no longer need those graphs and runs.
